# Clean Architecture + MVVM（项目选定后使用）

本文件是可选的应用架构契约。新项目先按 `vibe-flow` §4 讨论，根据业务、交互状态、设备/任务生命周期和维护成本决定是否采用；不是所有 GUI 的统一答案。Clean Architecture 规定源码依赖向内；MVVM 规定展示层职责。只改文件名、增加 ViewModel 类或消息通道不能证明符合。

## 适用与迁移

- 选定此架构的新应用按以下契约落地，语言、框架、交付路线仍按共用入口选择。简单界面可以选更小结构；CLI、一次性脚本、公司固件不套 MVVM，纯静态页面不造空层。
- 既有项目普通修改沿用已定架构，不因修 bug 自动迁移。明确迁移时先列职责、模块与需要禁止的依赖边，固定现有行为/数据契约；本次未迁移的边界建立精确基线，不用整目录忽略放行新增越界。
- 迁移范围超出授权时，说明完成这条职责链需要改哪些地方，由用户决定；不默认允许 View 绕过 ViewModel 调新用例。用户选择暂不迁移就保持现有行为，说明仍未迁移的边界，不报告成已符合。局部迁移只报告局部符合。

## 职责和状态所有者

| 职责 | 持有与执行 | 不应承担 |
|---|---|---|
| domain | 领域数据、业务不变量、纯规则 | GUI、网络、设备、数据库、配置文件读写 |
| application | 用例、会话/任务、恢复与退出清理；定义外部依赖 ports | 控件/窗口、具体驱动/数据库、界面刷新 |
| ViewModel | 展示状态、命令、输入格式校验、结果/错误到展示的映射 | 控件/窗口、实际 IO、业务流程与资源的最终所有权 |
| View | 控件/DOM、布局、绑定、框架线程调度 | 业务决策、直接调用用例或 IO、设备生命周期 |
| infrastructure/adapters | 实现 ports，封装驱动、存储、网络、系统调用 | 决定上层业务策略、反向更新窗口 |
| composition root | 读取配置、构造并注入依赖、连接事件、启动/停止入口 | 在入口重写业务工作流 |

业务状态只认 application/domain 的权威来源，ViewModel 的 busy、选择项、错误文字是展示投影；编辑草稿可以单独保存，提交时仍走业务校验。不能只靠按钮置灰保证业务互斥。

## 允许的源码依赖

- 典型命令链是 View → ViewModel → application → domain。它不是“只能调用相邻层”：ViewModel 可直接使用 domain 纯计算，View 可使用普通 DTO 类型；不能借此把业务操作放回 View，或把 IO/会话编排放回 ViewModel。不为简单计算造空转发用例。
- application 依赖自己或 domain 定义的 port；infrastructure 依赖并实现该 port，入口注入。运行时调用会执行 adapter，不代表内层可以源码依赖具体 adapter。
- 禁止内层导入外层实现，禁止 ViewModel 导入具体 IO，禁止 View 绕过 ViewModel 执行业务。合法的内层类型 re-export 可以使用；不能借 re-export、全局 service locator、任意回调或 `Any` 偷渡窗口/数据库/驱动句柄。跨界传普通数据、结果和明确契约。
- ttk/Slint 的 ViewModel 默认使用普通语言类型，不导入 Tk/Slint；DOM、框架对象转换、线程唤醒与属性绑定留在 View。其他已选框架若需要轻量绑定原语，架构讨论中明确允许的依赖与无窗口测试方式，不能笼统放行整个 GUI 包或借此持有窗口。没有该选择时沿用无框架依赖。
- 一个真实 IO 实现也需要窄 port，可用 Protocol、trait 或签名明确的函数。只声明实际操作，不为分层建通用 Repository、BaseViewModel、DI 容器或事件总线。测试替身不算第二个产品成员。
- 有具体 IO/工厂的注册表留在外层，通过入口注入的 catalog port/普通元数据/工厂契约使用；ViewModel/API 经 application 查询，不导入 adapters 注册表。纯规则注册表可留在 domain。
- 小应用可用几个文件，不要求多 crate/package；无领域规则不造空 domain。存在用例编排就独立于 View/ViewModel，不能以体量小为由塞回界面。

## 后台任务与生命周期

原生应用默认由 **UI 线程独占可变 ViewModel**。后台 application/adapter 仅产生普通结果事件，放入有界通道；View 在 UI 线程调度消费，调用 ViewModel 的 apply/drain 更新状态，再绑定控件。后台不能直接修改 ViewModel 或调用它的展示订阅者。无需后台工作时不造线程/队列；不默认用锁包住整个 ViewModel。

application 管任务标识、启动、取消、互斥和资源清理；adapter 管具体资源。过期会话、取消后结果按契约丢弃或记录，不能覆盖新会话。大日志用增量/窗口/限量快照，不每帧复制完整历史；小状态可用完整快照。

隐藏、后台继续运行和真正退出是不同意图。真正退出只有一个幂等用例：View 拦截关闭，ViewModel 请求退出并展示进度，后台停止接收新任务、结束/取消工作、释放资源；完成或按约定处理超时/失败后，View 解除订阅、撤销调度并销毁窗口。UI 不阻塞 join；重复点击和 composition 兜底复用同一退出状态，不另写一套清理。窗口销毁后不再投递展示更新。

例如串口应用：用例结束转发、释放占用，经虚拟口 port 清理本程序拥有的口并保存恢复配置；Windows/com0com adapter 执行操作。归属判定、顺序、失败是否允许退出是明确的业务契约，不放在按钮回调或 ViewModel。

## 原生与 Web 的映射

- ttk：`core.py / application.py / viewmodel.py / ui.py / adapters.py / app.py`。Tk Variable、after 与控件属于 View；after 在 UI 线程消费后台事件并更新 ViewModel。
- Rust/Slint：`lib.rs` 导出可测试的内层模块，`main.rs` 组装；`core.rs / application.rs / viewmodel.rs / ui.rs / adapters.rs` 按需存在。Slint 的 Weak、ModelRc、SharedString 由 View 桥接；UI 线程消费事件后更新普通 Rust ViewModel。单 crate 的模块拆分不是完整的编译依赖闸。
- 其他已选框架映射实际职责，不为迁就模板换框架；绑定依赖的允许范围按前述讨论明确。
- Web：浏览器 View → ViewModel → 注入的 client；client 实现 HTTP。服务器 API 是入站适配器，转换请求后调用 application → domain/ports。后端不依赖前端 ViewModel，业务规则由服务器权威校验。前端 ViewModel 不依赖 DOM/fetch；无需引入新前端框架。

## 验证要求

验证按本次规模与已选架构执行，不把每次小改升级成测试框架建设：

- **既有小改**：复用已有边界检查，跑代表性行为或必要的针对性测试；不因改文案、样式或单个行为新建 AST 检查器、夹具体系和全套分层测试。
- **新项目或明确的边界迁移**：架构讨论中确定可执行检查及范围，并落实到常规测试/CI；简单项目优先已有工具和最小行为测试。需要自建依赖检查时才建立项目专用检查器与正反夹具。未自动覆盖的边界人工核对并如实记录，不将人工核对称作自动闸通过。
- **检查不能只是口号**：实际命令、覆盖模块、允许/禁止的依赖和未覆盖范围写入 AGENTS；执行后报告结果。以下按本次涉及的边界选择，不机械要求每次补齐全部测试。

1. **依赖检查**：根据真实源码/模块依赖检查禁止边。优先编译边界或现有静态工具；有必要才写语法树检查。目录名、行数、关键词正则不能证明架构合规。单包编译成功也不等于禁止了所有反向导入。
2. **检查器自身**：新增或修改依赖检查器时，在隔离夹具中验证合法通过、违规非零；覆盖实际用到的 alias/re-export 等语法。动态加载、宏等未覆盖部分明确人工核对，别声称全语言完备。
3. **ViewModel 行为**：不启动窗口/DOM，不接真实 IO，执行实际命令并核对状态、错误和适用的取消/晚到结果。可用假用例，也可真实用例加假 port，或普通结果事件；不强制每个用例建接口，仅实例化不算行为验证。
4. **用例行为**：假 port 验证相关业务顺序、失败与副作用；纯规则测输入输出，不只验证 mock 被调用。Web 前端测试工具与运行依赖分开，具体做法见 Web 分支。
5. **真实界面与设备**：线程调度、绑定、输入、退出及交付产物仍按分支验证。上述自动检查不证明 GUI 或真机通过。

本技能给的是项目验证契约，不是已经替所有应用安装的架构闸。
