# 关窗与常驻：界面进程用完即退

架构讨论涉及「关窗后还要不要继续工作」时读；已有项目改关窗、托盘、后台常驻行为时也读。只管本应用自己起的桌面进程：浏览器访问或网站交付时，关网页不结束共享浏览器，服务按部署契约启停。

## 判定（用户 2026-10-27 定）

| 关窗后 | 进程结构 | 关窗行为 |
|---|---|---|
| 不需要继续工作（大多数工具） | 单进程 | 整个进程退出，不做托盘、不留后台 |
| 用户要求关窗后继续工作：串口/设备监听、定时任务、文件监视、给 CLI 或 AI 共用的服务 | 内核进程 + 界面进程 | 界面进程退出，内核继续；内核还占着设备或端口时先问 |

不因此拆进程的情况：用了后台线程、CLI 复用了业务代码、退出前要做有限的清理、「重开快一点」「以后可能要后台」。用户只要求关窗后把某件事做完（下载、导出），内核做完就可以退出，不必永久常驻。

**禁止隐藏窗口或藏到托盘而界面进程留着**：界面内存一点没省，本机样例里每个窗口进程约 100–550 MiB。

## 为什么是进程退出

- 最小化或隐藏窗口本身不保证释放私有提交内存，Windows 主要是裁工作集；不能凭任务管理器的工作集下降判断省了内存。
- 同一进程里销毁窗口和控件，框架运行时、字体库、渲染缓冲、分配器能还回多少说不准；进程退出才一定全部释放。
- 有的机器上，安全/加密软件或输入法会在进程第一次给**普通窗口**（隐藏的也算）跑消息循环时往里注入模块，每个带窗口的进程都多一笔固定开销，量级因机器而异，可达几十 MiB；只收消息的 message-only 窗口（父窗口为 `HWND_MESSAGE`）通常不触发。目标机器上有没有、有多大，按 [resource-check.md](resource-check.md) 实测。

本机样例（含该机的注入开销；2026-10-27 Codex 三样机，共用极简 Rust 内核，Private Bytes 中位，报告见 `gui-lifecycle-three-demos/docs/RESULTS.md`）：界面打开时 Slint 124、ttk 114、WebView2 552 MiB，界面进程退出后都回到内核的 0.7 MiB；重建到界面就绪 Slint 151 ms、ttk 646 ms、WebView2 3.1 s。内核只是计数器，真实业务内核要另测；数字只代表这台机器和这组样机。

## 拆进程时的契约

- **关界面不停业务**：关闭界面只保存展示状态、退订、退出界面进程，不取消任务、不释放设备。整体停止才走真正退出的幂等用例，见 [clean-mvvm.md](clean-mvvm.md#后台任务与生命周期)。
- **内核是业务状态唯一来源**：连接、会话、任务、队列、原始记录都在内核。窗口位置、页签、筛选这类展示偏好关窗前存本地，存失败记一笔照常退出；用户的编辑草稿沿用项目的保存契约，保存失败就取消关闭或让用户明确放弃，不静默丢。
- **内核不建普通窗口**，隐藏的也不行。确实需要窗口消息时用 message-only 窗口，但它收不到广播：托盘图标要自己处理资源管理器重启后的恢复（例如定时检查、失败就重新添加），其他系统通知逐项核实能不能收到。目标机器有注入时，验收查内核和托盘进程的模块列表里没有被注入的模块；内部会建普通隐藏窗口的托盘库不用。
- **通信**：沿用项目已有的跨进程协议；新项目优先本机 HTTP/WebSocket 加令牌，方便 CLI 和 AI 也连同一个内核。契约按共用入口「通信按实际边界选」记录。
- **单实例与启动**：同一数据目录用原子的实例占用（命名互斥量或独占锁文件）保证只有一个内核，并发启动时后到的连接已有内核，不另起。界面找不到内核就起一个，等内核报就绪再连；连不上或中途失联时显示断线并允许重连，不自己再起第二个。界面默认只开一个。
- **重开补齐**：重开就是再启动一次界面进程，连上后先取当前状态，再接后续变化。需要连续记录的（日志、采样）按游标或序号补齐关窗期间的数据，不丢不重。
- **关窗时说清楚**：内核还占着设备、端口或有在途任务时，关窗先问（例：停止并退出 / 继续后台 / 取消），不能让用户以为已经退出、资源却被占着。没有占用时直接关界面，内核按项目约定继续或空闲退出。
- **整体退出**：只走一个幂等的停止入口（按钮、托盘菜单、CLI 共用），内核确认停止并释放资源后才算退出完成。界面进程退出不能带走内核；内核退出后界面显示断线或随之退出，不留孤儿。
- **最小化释放界面不是默认**：重开有冷启动成本，每次最小化都销毁体验差。项目确有需要时单独谈定延迟时长、恢复入口和不能释放的情况。

## 验证

用临时数据目录和假设备，走一遍：打开 → 关窗选继续 → 界面进程消失、内核 PID 不变且仍在工作 → 重开 → 状态恢复、关窗期间的数据不丢不重 → 整体退出后进程组清零。另测：同时启动两次只有一个内核；分别强杀内核和界面进程各一次，另一方行为符合上面的契约；反复关开十次，没有残留进程，界面每次重开的内存不逐次上涨。有托盘的再测资源管理器重启后图标能恢复。内存按 [resource-check.md](resource-check.md) 算整个进程组。
