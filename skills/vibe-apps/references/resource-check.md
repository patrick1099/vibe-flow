# 资源实测

只在用户对内存 / CPU 提了要求，或要拿资源数据比较两种方案时读。

## 怎么测才算数

- **同条件比**：同一台机器、同样的数据量和接收速率、同样的可见行数。记下 Python 与库的版本（Rust 用 release 构建并注明渲染后端）和采样时间。
- **算整个进程组**：应用起的子进程（WebView、服务端）一起算。说明测的是工作集还是私有提交内存；GPU 显存没测就写明没测。
- **最小化不等于省内存**：最小化或隐藏窗口本身不保证释放私有提交内存，不能只凭工作集下降判断；比较「释放界面」方案看私有提交内存，并确认界面进程确实退出。
- **注意环境带来的固定开销**：安全软件、输入法等可能往每个带窗口的进程注入模块（见 [gui-lifecycle.md](gui-lifecycle.md)）。比较框架时这笔两边都有，剩下的差值才归框架；换机器要重测，不当固定成本用。
- **测几个时刻**：冷启动、空闲、加载长日志、持续运行一段时间。看的是有没有一直涨，不只是某一刻的数。持续多久按实际用途定，不必每个小工具都跑通宵。

## 别这样下结论

- 一次几分钟的样窗短测，不能推广成「某框架更省内存」的通用排名。
- 安装包体积和运行内存是两回事，不用前者推后者。
- 换成 Rust 不等于自动省内存，同样要拿 release 产物实测。
