# scan-field：对外扫同款（开工前借点子 / 完工后找升级方向）

## 总纲

> 真正的浪费只有一种：**不知道同款存在**——既没借到好点子又白花时间。规则不是「禁止造轮子」，是「**动手前先看过**」。

个人工具造轮子不天然是罪：握着源、贴合工作流、能自己改都是收益。所以本 skill 从不劝退，只负责让你**在知情的前提下**决定。

**一进门先分岔**：用户在**开口**（要新建或重写一个东西）还是**回头**（东西做到能用了）？两头共用同一套搜索机制与原创度判据，**产物厚度差一档**：开口那头几句话，回头那头一份文档。

**为什么有两头**（cut-scope 只有一头）：cut-scope 与本 skill 是「对内剪枝 / 对外比同款」一对，但时间性不同——**设计膨胀只会事后发生**，而**「不知道同款存在」的代价在开工前最大**。故 cut-scope 只有事后一头，scan-field 两头都有。

## 缩放闸（先过这道，否则违反「小事要省」）

**开口那头只在以下情形跑：**

- 要新建一个**能拿出去**的东西：插件 / 工具包 / 产品 / 会长期活的工具。
- 打算**重写或替换**一个已有的东西（自己的或别人的）。

**不跑**：日常改功能、加子命令、修 bug、一次性微脚本、只是换个参数。**不命中就一个字都不提**——别为了显得周全去扫一遍市面。

**回头那头**：东西做到能用了、想知道生态位才跑；还没有可对比的东西就别跑。

---

## 开口那头：便宜地扫一遍（薄，不落文档）

目标是**决策输入**，不是文档。一屏封顶、几分钟，主线直接搜即可。

1. **定锚**：用一句话说清「是什么 / 给谁 / 解决什么」。没有就先跟用户敲定这一句再搜——无锚必搜偏。
2. **搜 2–3 类源**：GitHub / 插件或包市场 / 博客与生态讨论。量不大就主线直接搜，别起 subagent。
3. **结论只有三种，明说是哪一种**：
   - **有能直接用的同款** → 说清它是什么、用它的代价（装什么、缺什么），建议直接用，**别做**。
   - **有邻近款** → 列 1–3 个能抄的点（思路 / 架构 / 生态位 / 交互），再动手。
   - **没搜到** → 说「**没搜到**同款」，不说「没有同款」，然后放心做。
4. **用户仍要自己做就不劝**——「已经看过同款」这个事实本身就是本步的全部价值。

产物：对话里几句话 + 关键链接。**不产文档、不建目录**（要落盘那是回头那头的事）。

## 回头那头：产对比文档（厚）

搜索锚 = `docs/BLUEPRINT.md`（是什么、给谁、解决什么）。无蓝图则先跟用户敲定一句话定位再搜。**广义「更好」，不止运行时性能**——思路、架构、生态位、能抄的好点子都算。

### subagent：研究 fan-out

把 web / GitHub / 插件市场搜索关进子代理、主线只收摘要，可**并行多源**（对应 superpowers 类框架的 `dispatching-parallel-agents`）。

**每个 research subagent**：给它「项目一句话 + 关键特征 + 要搜的一类源」，让它只回：同款名 + 链接、它做了啥、跟本项目的异同、能抄的点。主线**汇总**成对比表，不把原始搜索噪音带进主上下文。

**缩放**：只想快速扫一类源、量不大，主线直接搜也行；要广扫多源才起并行 subagent。

### 产出格式（沿用生态对比模板）

```markdown
# <项目> 生态对比与升级方向 (日期)
> 结论一句话：…
> 教训：重写前先花几分钟搜 GitHub / 插件市场 / 博客。

## 原创度对比表
| 自制 | 市面同款 | 原创度(🔴红海/🟠撞款/🟡邻近/🟢原创) | 差异点·我独有 |
|---|---|---|---|
| … | … | 🟠 撞款 | … |

## 未来升级方向(按优先级)
### 🔴 去红海抄思路
### 🟠 站肩膀差异化
### 🟢 继续深耕真差异

## 判断准则
（重写前先看过同款；真正的浪费只有一种:不知道同款存在。）

- <类目>：[名](链接) · [名](链接)
```

## 与邻居划界

- `cut-scope`：对内剪枝已膨胀的**设计**；本 skill 对外比**同款**。见上「为什么有两头」。
- `vibe-flow` §3「开工前先看有没有现成的」：那一步先查本机脚本登记册（`script-manager` 的 INDEX，有现成的就直接复用）；**查完仍要新建或重写，且过了上面的缩放闸，才路由到本 skill 的开口那头**。一个查自己有没有，一个查市面有没有。
- ≠ 分支收尾并入（`superpowers-manual` 的 `finishing-a-development-branch`）。
- **两头都只产结论 / 文档，不改项目代码与设计。**

## 反模式

- 开口那头写成完整对比文档 / 建 docs 文件（那是回头那头的事，开口必须便宜）
- 缩放闸没过就扫：给一次性微脚本、日常改功能也去搜一遍市面
- 把「没搜到同款」说成「没有同款」
- 用户已知情并决定自己做，还反复劝退（本 skill 从不劝退）
- 搜完只堆链接、不判原创度 / 不给方向
- 搜索无锚（先要那句「是什么 / 给谁」，否则搜偏）
- 把重搜索噪音塞进主线上下文（该用 subagent fan-out）
- 顺手改项目代码（越界）
- 只盯运行时性能（要广义「更好」：思路 / 架构 / 生态位）

## 版本记

v0.2.0：从「只管完工后」改成**一进门先分岔的两头**（开口 / 回头），共用搜索机制与原创度判据，产物厚度差一档，并加缩放闸。原因：旧版正文写着「重写**前**先看过同款」，触发条件却写「不用：还没做出可对比的东西时」——自相矛盾。旧版把时点定在事后是从「与 cut-scope 对称」继承来的，不是从价值推出来的。形态照 `clarify-needs`（同样是一个 skill 管开口与回头两头）。
