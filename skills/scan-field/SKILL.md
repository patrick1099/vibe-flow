# scan-field：对外扫同款，产升级方向

## 总纲

> 一个东西做完后，去市面上搜同款与更优方案，产出「原创度对比 + 升级方向」文档喂下一轮。**广义「更好」，不止运行时性能**——思路、架构、生态位、能抄的好点子都算。

## 何时用 / 不用

- **用**：项目 / 工具做到能用了，想知道生态位、能抄的好点子、该站的肩膀。
- **不用**：还没做出可对比的东西时。

## 与邻居划界

- ≠ 分支收尾并入（`superpowers-manual` 的 `finishing-a-development-branch`）；scan-field 是完工后**向外反思**。
- **只产文档，不改项目代码 / 设计**。
- 搜索锚 = `docs/BLUEPRINT.md`（是什么、给谁、解决什么）。无蓝图则先跟用户敲定一句话定位再搜。

## 判断准则

个人工具造轮子不天然是罪——握着源、贴合工作流、能自己改都是收益。真正的浪费只有一种：**不知道同款存在**，既没借到好点子又白花时间。规则不是「禁止重写」，是「**重写前先看过同款**」。

## subagent：研究 fan-out

把 web / GitHub / 插件市场搜索关进子代理、主线只收摘要，可**并行多源**（对应 superpowers `dispatching-parallel-agents`）。

**每个 research subagent**：给它「项目一句话 + 关键特征 + 要搜的一类源（如 GitHub / 插件市场 / 博客生态）」，让它只回：同款名 + 链接、它做了啥、跟本项目的异同、能抄的点。主线**汇总**成对比表，不把原始搜索噪音带进主上下文。

**缩放**：只想快速扫一类源、量不大，主线直接搜也行；要广扫多源才起并行 subagent。

## 产出格式（沿用生态对比模板）

```markdown
# <项目> 生态对比与升级方向 (日期)
> 结论一句话：…
> 教训：重写前先花几分钟搜 GitHub / 插件市场 / 博客。

## 原创度对比表
| 自制 | 市面同款 | 原创度(🔴红海/🟠撞款/🟡邻近/🟢原创) | 差异点·我独有 |
|---|---|---|---|
| … | … | 🟠 撞款 | … |

## 未来升级方向(按优先级)
### 🔴 去红海抄思路
### 🟠 站肩膀差异化
### 🟢 继续深耕真差异

## 判断准则
（重写前先看过同款；真正的浪费只有一种:不知道同款存在。）

## Sources(搜索日期)
- <类目>：[名](链接) · [名](链接)
```

## 反模式

- 搜完只堆链接、不判原创度 / 不给升级方向
- 把重搜索噪音塞进主线上下文（该用 subagent fan-out）
- 顺手改项目代码（越界，只产文档）
- 搜索无锚（要用 BLUEPRINT 的「是什么 / 给谁」当锚，否则搜偏）
- 只盯运行时性能（要广义「更好」：思路 / 架构 / 生态位）
