# 深挖版：完整需求归位与分级

> **这是你（AI）的内部推理工具，不是给用户看的模板。** 跑完这一整套，**给用户的出口照样只有大白话**（见 SKILL.md「给用户永远大白话」）：不许把下面的表格、角色名、档位名、"Appetite"这些术语甩给用户。
>
> **什么时候在这儿**：你是按 SKILL.md「何时拉厚版」的触发门进来的（需求真多 / 两个以上目标 / 分不清手段偏好约束 / 用户要深挖 / 你对分级没把握）。**微任务不该到这儿**——真到了，退回缩放闸。

## 一、5 角色透镜（归位的骨架）

把用户每句原话按**角色**归位——这是**透镜，不是要逐格填满的表**：

| 角色 | 核心问题 | 默认处理 |
|---|---|---|
| 目标 | 用户最终想改变什么？（换掉所有实现方式后它还成立吗） | 保护核心目标 |
| 手段 | 准备用什么办法实现？ | 默认可替换 |
| 验收 | 做成什么样才算能用？（把"美观""稳"翻成可观察标准） | 先定最低及格线 |
| 约束 | 哪些边界不能突破？（有明确来源和违反后果吗） | 区分硬约束 vs 偏好 |
| 交付 | 谁以什么形式拿到？ | 只做首批真实用户要的形态 |

**铁律：按语境归位，不按关键词机械分类。** 同一个词角色可能不同：

- "共享给同事协作"可能是**目标**；"生成分享链接"是**交付**；"部署成网站方便共享"是**手段**。
- "代码体积小"有明确设备上限时是**约束**，没上限只是**质量偏好**。
- "必须用 Python"来自部署环境限制是**约束**，只是习惯则是**偏好/手段**。

**为什么是 5 角色而不是 10 话题维度**：话题表（省力/复用/性能/美观/共享…）自己就混层级——"可复用"只是"省力"的一种手段。真正治痛点的是**角色**这根轴，不是话题。话题降级为下面的「防漏清单」。

## 二、证据一问（治"别信嘴上的"）

对每条可疑需求，当成**一个问题**问，不搞 E0–E3 分级打分：

> **这是他真遇到的，还是他猜的 / 听说的 / 想象未来会用的？**

vibe coder 嘴上的需求未必是真需求。没有真实证据的，往"当前不做"挪，别急着排进核心。

## 三、4 档分级（跟角色是两列，别混成一根轴）

| 档 | 含义 |
|---|---|
| 核心 | 删了项目就没存在意义（核心用户/核心问题/核心结果） |
| 底线 | 缺了它，核心目标就无法真实落地（最低验收、硬约束、必要交付） |
| 可换可降 | 有价值，但做法可替换、程度可降（首选手段、体验优化、工程偏好） |
| 当前不做 | 挂不回目标 / 重复 / 无证据 / 成本失衡 / 面向假想未来——**含"延后"和"放弃"两种** |

**"目标不砍"要修正**：不是所有目标都不砍。准确说——**核心目标不因实现困难被偷偷删除；次要目标、后来冒出的新目标，可以拆分、延后或放弃**。一个项目最好只有一个核心目标；多个互相独立的核心，通常意味着该拆成多个项目/阶段。

## 四、劝退五问（**先在 AI 内部逐条判断**）

**这五问先由你自己在心里对每条可疑需求过一遍，不是拿去审问用户。** 只有当某个答案**你不知道、且它会改变归位或分级**时，才向用户追问——**一次只问一个最关键的**，别把五问乘以每条需求甩成连环审讯。

1. 删掉它，核心价值会消失吗？
2. 换一种实现，用户还满意吗？
3. "做好"的失败标准是什么？
4. 这是现实强制，还是个人偏好？
5. 首个真实用户现在就需要它吗？

## 五、Appetite（固定投入，范围可变）

问的是**"这问题最多值得花多少成本解决"**，不是"估计做完要多久"。装不下时，**按固定顺序砍，绝不偷删核心目标/最低验收**：

```
归入当前不做（含延后）→ 降级可换可降 → 换更便宜的手段
→ 缩小交付面 → 质量降到最低验收 → 拆出次要目标
```

仍放不下，就让用户三选一：**加投入 / 缩拆目标 / 暂不做**。

## 六、挖到什么程度算够（停手判据）

停在一个**甜区**，同时满足：

1. **剥干净可替换的实现手段**——锚里不含那些**可以换**的方案词（"用 Excel""做个按钮""写爬虫"），只剩"想达成什么 / 想少受什么罪"。**但不可替换的外部协议、运行环境、合规要求（Modbus、必须离线、Win7）不是手段，归约束，不许剥。**
2. **还没滑到空泛动机**——停在"少造什么轮子 / 省什么力 / 少犯哪种错"这层；再往下问"为什么想省力"就是空话，砍掉。

例："给我做个爬虫抓这些网页存 Excel" → 剥方案 → "想把散在几十个网页的数据凑一张表" → 再问一层 → "我每周手动抄这些，烦死了想省这个力"（**停这儿**）。

## 七、防漏清单（可选提醒，不参与排级）

主链走完后，用 **"快、省、用、爽、稳、传、安、控"** 自检有没有漏问某类关注点（离线？以后自己能改？隐私？多设备？）。

**铁律：防漏清单只负责提醒你去问，不自动产生需求，更不参与排级，也不许拿它去给微任务加功能。**

## 八、理论来源（只当读物，一个字不进操作指令）

BMM / KAOS（目标 vs 手段）、Impact Mapping（目标→交付因果追溯）、Continuous Discovery Habits（真需求 vs 未验证的猜想）、Shape Up（Appetite 固定投入、范围可变）、Software Requirements / ISO 29148 / ISO 25010（正式底座，不整套搬）。轻量版只借骨架。
