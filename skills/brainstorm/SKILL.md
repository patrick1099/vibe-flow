# brainstorm：多 agent 头脑风暴（只在你叫的时候跑）

## 总纲

> 平时的外援是「主 agent 先出方案、决策者挑毛病」（[collaboration.md](../vibe-flow/references/collaboration.md)），它会锚定：审的人只围着给定方案改，不会说「整条路换掉」。头脑风暴在方案还没出来时先发散、再收敛。

主 agent 在这里只当**主持**：出简报、派视角、匿名、转运材料。**不出方案、不表态**，转交时也不加自己的倾向。推荐由主席给，拍板归用户。

只用于个人项目；公司固件 / 产品代码不适用，被叫到那里就直说。

## 先过一道：这步值不值得讨论（只提醒一次）

**同时满足**下面两条，才说一句「这步不用讨论，审一下就行」，并指向 collaboration.md 的方案审或结果审：

- 没有需要重开的路线问题；
- 眼下只需要按既定标准审查或执行（例如代码已写完只差审查）。

只提醒一次。用户坚持就照跑，不要求他证明价值。**不以「项目小」「代码已写完」单独作为劝退理由。**

## 席位

| 角色 | 谁 | 怎么派 |
|---|---|---|
| 主持 | 主 agent | 不参与出方案 |
| 席位 S1–S3 | 3 个 GPT 席 | `ai-room ask --to codex` |
| 席位 S4 | 1 个 Opus 席 | `ai-room ask --to claude` |
| 主席 | **另开的新 Opus 会话**，不是 S4 那个 | `ai-room ask --to claude` |

- 全部 `read-only`，`--cwd` 指项目根，席位可读项目代码核对事实。
- 模型和思考档位走 ai-room 默认（`models.toml` 是唯一出处），命令里不写 `--model` / `--effort`。
- 本模式是 collaboration.md「只问对面那一个决策者」的例外：主 agent 是 Codex 时同样派 3 + 1。
- 题目文本直接放进 `--question`；不要让席位去读主持新写的文件（本机有 Esafenet，主持组装参数时用能读出明文的方式取文件内容）。

## 流程

**0. 运行目录。** `<项目根>/.ai-room/brainstorm/<YYYYMMDD-题目>/`。简报、各轮原文、匿名映射、纪要都由主持写在这里；席位只读，不写答卷。`.ai-room/` 由 ai-room 自带的 `.gitignore` 忽略，没有就先建（内容 `*`）。另记一份 `run.md`：每席的轮次、session_id、状态、匿名映射。

**1. 简报（`brief.md`）。** 不写任何方案或倾向，免得锚定。

- 题目一句话；用户要的可见结果。
- 条件分三栏：**硬约束** / **偏好** / **可重议的假设**。来源是 HANDOFF「已谈定」、`NEEDS.md` 和对话；已谈定的结论不自动都是硬约束，过去的技术假设放第三栏。
- 验收：怎样算好方案。
- 相关文件的精确路径。

**2. 派视角（写进 `run.md`）。** 视角不固定，从这道题的真实矛盾里找。每席三行：

```
题目条件：……（这道题里让这个视角成立的事实）
优先检验的取舍：……
推翻条件：出现什么就放弃这个方向
```

- 主要的对立两极：一极给 Opus 席，另一极给某个 GPT 席，不让同一家模型把正反两边都演了。
- 其余 GPT 席探**不同维度**，不是同一条轴上的中间值。三个 GPT 只拿人设名，容易换措辞不换路线。
- 可以让一席质疑「到底需不需要新建 / 改」，在硬约束之内。
- 不指定具体方案，不为凑分歧硬造对立。

**3. 第 1 轮：盲出方案（4 席并行）。** 每席收到：简报全文 + 本席视角 + 下面的格式。正文 ≤800 字，证据 ≤5 条，可以短写。原文存 `r1-S1.md` … `r1-S4.md`。

```
## 方案（一句话）
## 怎么做
## 假设（每条标 FACT / INFERENCE / ASSUMPTION / UNKNOWN；FACT 附 file:line 或来源）
## 代价
## 反证：什么情况说明这条路错了
```

**4. 匿名。** 去掉席位和模型身份，标成 A–D；**每给一位读者都重新打乱顺序**，映射只记在 `run.md`。不改写方案文字，免得主持的转述成了新的过滤。

**5. 第 2 轮：交锋（按需，默认不跑）。** 只有出现「会改变路线、且能靠交锋澄清」的分歧才跑。缺代码事实就由主持查证或标未知，缺用户偏好就留给用户拍板，这两种都不靠交锋补。

跑的时候：挑持对立意见的一个 GPT 席和 Opus 席，**各开新会话**（不续用第 1 轮的会话，否则它知道哪份是自己的、会转去防守）。给简报 + 匿名四案 + 要回应的那个分歧；每案意见 ≤120 字，允许写「无异议」但要给依据。原文存 `r2-*.md`。

**6. 主席。** 新 Opus 会话，输入简报 + 匿名四案 + 交锋意见（有的话）。纪要 ≤800 字，存 `chair.md`：

```
## 未解决的分歧（写在最前）
## 共识
## 推荐方案与理由
## 为什么没采纳最强的那条反对意见
## 少数派意见（保留，不抹平）
## 什么情况说明推荐错了
## 下一步（一个具体动作）
## 需要用户拍板的点（翻译成用户感知得到的后果）
```

要求：重复的论据合并，**几席说同一句不算多票**，不按票数收敛；关键结论保留 FACT / ASSUMPTION 标签。

**7. 交给用户。** 主持原样转交主席纪要，附：四案各一句话摘要（此时可揭示哪份出自哪席）、缺席情况、实际调用次数。主持不加自己的倾向。用户拍板。

**8. 记下来。** 用户拍板后，按 [vibe-flow §4](../vibe-flow/SKILL.md) 在 HANDOFF「已谈定」记一条，来源写「头脑风暴采纳（运行目录名）」。这个方案**不再**走 collaboration.md 的方案审，免得同一件事买两遍。不另建文档，运行目录留在本地供回看。

## 预算与失败

- **调用次数**：默认 5 次（4 席 + 主席）；跑交锋是 7 次。并行省的是时间，不是钱；限篇幅只限输出文字，不限思考消耗。
- **截止**：单席以 ai-room 的 `max-runtime` 为上限，第 1 轮最多等这么久。超时的席位最多续接一次，**显式指定**那一席：`ai-room resume --to <codex|claude> --session <它的 session_id> --cwd <项目根>`，不用默认的「续最近一个」（会续错席）。还不回就按缺席收口。
- **缺席 / 失败 / 空输出**：纪要里写明「S2 缺席（超时）」，不当成同意。有效方案少于 2 份就停下告诉用户，不出推荐。

## 反模式

- 主持写自己的方案，或转交纪要时加倾向
- 自己触发本 skill，或以「项目小」为由劝退
- 把「已谈定」全部当硬约束塞进简报
- 每次套同一组固定视角；三个 GPT 席只给人设名
- 默认跑交锋；交锋续用第 1 轮会话
- 主席沿用 S4 的会话；按票数收敛；三个 GPT 说了同一句算三票
- 把缺席或空输出当同意
- 头脑风暴之后再把同一方案送决策者审
