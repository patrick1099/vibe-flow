# 外援：何时咨询，审到哪里

执行负责人仅在需要委派、出现新的实质技术取舍，或好档关键结果复核时读；小改不为流程咨询。档位和已完成的方案评审由派工传入，不重新判档或重复审同一方案。

以下外援规则中，**执行负责人**指直接实施时的主 agent，或监工模式里的监工。

角色固定：**claude 和 codex 是决策者（你是 claude 就问 codex，反之亦然），opencode 只当执行者。** 怎么调用、上下文怎么给、超时怎么续，全归 `ai-room` skill，本节只管**什么时候叫、审多少**。

- **咨询决策者**：需求已经清楚、且仍有一个会实质影响架构、可维护性或迁移成本的技术取舍，才叫。交的是**你自己的方案**让它挑毛病，一次一个具体问题。决定要叫就直接派，不反问用户。
- **派执行者**：没有技术取舍的机械活（批量替换、格式化、补样板、跑测试摘失败……）直接派。有取舍的，先让决策者把方案定下来再拆成任务派；方案审过一次，拆出来的任务不必每件重审。
- 决策者说“需要用户拍板”时，只有真跨过 [../SKILL.md](../SKILL.md) §4 用户决策边界才去问用户，否则自己定。
- 审完采纳或否决了什么，直接执行时按 [../SKILL.md](../SKILL.md) §4 当场记一条；监工将纯技术结论记在批次证据，只有涉及有效约定变化才短报主会话，由主会话更新「已谈定」。台账只记问了什么，不记结论。

| 情形 | 咨询密度 | 能不能派 opencode |
|---|---|---|
| **机械活**（无技术取舍） | **不咨询** | 随便派，鼓励派 |
| **省档** | 不叫外援 | 实现里的机械部分照样派 |
| **好档 · 轻**（升档理由是「范围或影响面大」「关键未知」「多目标纠缠」） | **只审方案**：开工前咨询一次，之后冒出**新的**实质取舍才再咨询 | 方案定稿后拆任务派 |
| **好档 · 重**（命中「出错后果重 / 不可逆」，或要给别人且本次改动范围大） | **方案审 ＋ 关键步骤结果审**：关键步骤做完送回决策者过一眼；机械步骤不逐个审 | 同上，逐步派 |

「重」不是第三个档位，是好档内部按已有判据再分；判档仍然只判一次。

**头脑风暴**（`brainstorm` skill）只由用户手动调用，不在上表里，也不由本文件触发。用户拍板采纳的头脑风暴结论算已审方案，不再送决策者做方案审；之后冒出新的实质取舍，或好档·重的关键步骤结果审，仍照上表。

**停止条件**：同一个问题不二次送审；决策者说通过就往下走；连续两步没有新问题就停止回审，剩下的自己复核。执行者的产出一律由执行负责人复核——监工模式下由监工组织验证，不把逐项复核退回主会话。
