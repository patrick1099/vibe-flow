# clarify-needs 版本记

从 `skills/clarify-needs/SKILL.md` 末尾挪出（2026-09-24，vibe-flow 0.12.0 瘦身）。只记当时为什么这么改；其中的触发条件等规则以 SKILL.md 当前版本为准，这里的旧说法已作废。

vibe-flow 0.13.2（2026-09-24）：**第二层「我打算怎么搭」从按需改回好档多模块时默认画。** 用户澄清自己懂架构（模块、数据流、流程图）、不懂代码，此前把第二层也藏起来属于改过头。图停在架构层，是告知不是审批；架构词首次带一句解释即可用。

v0.7.1（2026-09-23）：**运行模型图加第二种画法：分层结构用 HTML 片段。** 用户拿两张系统框架图（Zephyr 分层、燃气表 APP/Driver/HAL/BSP）问能不能画——这类图靠嵌套与对齐表达，D2 的自动布局摆不出来（与 slide-flow「摆放类用 HTML/CSS、连线多的用 D2」同一条分工）。`model_page.py` 按后缀分流：`.d2` 照旧，`.html` 片段只许用一套固定类名（band / layer / row / box / chips / gap / guess），样式由脚本统一加，防每次手搓走样。判据写进 `references/run-model.md`：去掉所有箭头图还剩意思 → 分层结构。

v0.7.0（2026-09-23）：**开口那头加第 5 步「画运行模型图」。** 用户原话："光理解我需求，颗粒度还是太低了……想要能画出流程图之类的运行模型，让我知道你大概会怎么做。"一句锚把出错路径、介入点、产出形态都压没了，分歧要等代码写完才暴露；图逼着每个分岔落一个框。两层分开放：第一层"它跑起来是什么样"留在本 skill（仍是需求），第二层"我打算怎么搭"放 `vibe-flow` §4（是方案，不破本 skill 不拍方案的边界）。载体选型经用户逐轮挑过：ASCII 只当降级；mermaid 嫌丑；D2 出 PNG 嫌糊；定为 **D2 矢量图嵌本地 HTML 页、平整风**。样式与页面骨架固化进 `scripts/model_page.py`（stdlib），模型只写框和线，避免每次手搓 HTML 走样。细则见 `references/run-model.md`。

v0.6.0（2026-08-07）：**摘掉 `disable-model-invocation: true`，改成自触发 + description 限流。** 硬闸的实际效果不是"低频"而是零——模型连 skill 列表里都看不到它，真正需要它的项目场景一次也进不去，全靠人记得敲。代价是小活可能被误伤，用两道软闸压：description 里写死「只在东西会长期活下去时自触发，微任务/改 bug/纯问答不起」，正文 §何时用 加"自触发的闸"与"用户喊停优先"两条。同步改了 `vibe-flow` §4 路由（原文写着"你无法自己启动它"，反向压制）和它的反模式清单。

v0.5.0（2026-07-30）：总纲加**"手段说太死 / 目标说太空"的失衡轴**——把原来"混在一层"这个对称说法换成有方向的不对称，并点明三步（挖目标 / 偏好vs约束 / 验收翻译）各治哪一头。借自 Anthropic 认知四象限那篇的 spec 平衡论（**纯换框架，零新机制**；其余三格已被现有做法覆盖或已划界给探方案，未知未知那格刻意不收）。理由与不收的部分见 `references/deep-needs-analysis.md` §八 与插件 `docs/history/2026-07-30-fable-四象限借鉴.md`。

v0.4.0：reality-check → clarify-needs。回头从"按功能盘点"改成"按需求盘点"（功能视角已废）。结构改为**薄核 + 厚兜底**：默认路径只放实测有效的（挖目标 / 轻查偏好·验收 / 回头 / 诚实边界 / 缩放闸），5 角色·4 档·劝退五问·Appetite·防漏清单收进 `references/deep-needs-analysis.md` 按需加载。
