# vibe-flow 蓝图

给个人脚本、工具、应用或插件的构建/修改请求，按本次改动判断流程厚度，路由必要的需求、方案、实现与验证；明确的小改保持简短。公司固件遵守其自身规则。

应用界面沿用项目 DESIGN.md 和用户确认的样例。新建上位机默认读取已安装的本机工业上位机预设，直接复用其设计规范、尺寸和样例。OpenDesign 可作为效果图先行的原型入口：小型效果图在当前会话直接出图，要求 OpenDesign 生成或验证体系继承时走已配置的生成入口。

每项任务开工前，配置只给出工具、agent、角色、模型、思考程度和组织建议；用户集中确认或明确授权后，记录本次 Markdown 执行约定再派发。更改组合先确认受影响部分。已授权子任务不重复问。恢复从原约定取设置，核对同一工作树、会话、模型、权限和现有结果，不重发同一任务。

配置格式为 version=1 的 JSON，必须含 tools/agents/roles/organizations；结构错误、坏覆盖或未知路径符号明确失败，不能回退模型。选中组织依赖的工具说明缺失时失败；未选中工具不可用只标原因。读取输出为解析后的建议与来源，不启动 agent。换成员只改配置及该工具说明，调用方不散写成员名单。

有实质取舍才方案审，机械活直接派，已审同一方案不重复审。执行者结果由负责人核验真实文件和有意义的测试。点名才启用监工，头脑风暴只手动触发：独立盲提案、逐读者重排匿名、按需新会话交锋、全新主席、少数意见保留，用户拍板。提案并行不表示主席同时开始。

文档、压缩恢复与依赖快照的既有行为继续保留；宿主事件与验证边界见 SETUP 和 hooks-validation。本次不改现有文档闸语义。

不提供厂商驱动、执行框架、兼容 CLI、二次结果协议，不自动迁移或删除历史会话数据。工具说明可作为配置数据复用，随包上游原文附版本、许可、来源和同步入口，并放在插件根 vendor/，不暴露成额外可调用 skill 或必装依赖。机器路径只在本机配置保存。以上未列内容均为实现细节。
